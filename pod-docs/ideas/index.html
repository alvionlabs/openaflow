One list of error codes, and clear messages in every form

Give every failure in OpenAFlow one defined error code, as a word (already_registered, no_claim, config_unwritable), not a number. Keep the codes in one shared, typed list that the server and the web app both use, with one line on what each means. Then: - Every form turns a code into a short, warm message (the style the human picked on 2026-11-13 in PR #113: "This repo is already here", "Something went wrong. Please try again"). No raw server word or HTTP 500 reaches the screen. - The exact code and HTTP status go to the console, and to the app's log file in the desktop app, so a bug report can name them. An optional muted Details line with a copy button can show them. - The build fails when a code has no message.

Why it waits

It touches every server route and every form, so it is bigger than PR #113, which only does Add repo, Remove repo, and Forget.

Worth building when

Before v0.1.0. The human, on 2026-11-13: "I think this one is crucial for the release because it helps us track bugs."

Run event log mod

A small mod in the pod plugin (TypeScript, the same mechanism as pod-flow) writes one JSON line per event to <repo>/.claude/pod/events.jsonl: pod:* skill prompts (run start and stage), pod:* agent start and end with the slice parsed from the dispatch, and gh pr create / gh pr merge calls. Each event carries the session id and a v format version. The folder self-ignores with a .gitignore holding *. See layer 2 in docs/master-plan.md.

Why it waits

Phase 1 (pod-docs/plans/board-read.md) builds from Markdown and transcripts first, since that fallback must exist anyway, and mods are early access in Claude Code.

Worth building when

Phase 1 in real use shows Markdown and transcripts are too slow (updates over 5 seconds) or ambiguous (wrong run or slice mapping).

CLI runner

superseded by research/terminal-host.md (2026-11-11)

The board's server runs your own claude binary with your own login: - Step in (phase 3): claude in a pseudo-terminal (node-pty), shown in the browser with xterm.js over a WebSocket, so you can type into an engineer's session. - Runs without a chat (phase 4): claude -p --resume <session> --output-format stream-json "continue", rendered as board events, to resume after go or continue and start runs from the board.

Why it waits

Phase 1 is read-only, and phases 3 and 4 are decided after using phases 1–2. node-pty is a native module with build risk on Windows, and Anthropic's headless billing rules changed several times in 2026.

Worth building when

After phases 1–2, stepping into engineers or resuming runs from the board is still the main friction, and Anthropic's current policy allows running the user's own claude this way.
